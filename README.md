# MeowMusicSync

Бот для двусторонней фоновой синхронизации любимых треков между **Spotify** и **Яндекс Музыкой**.

## Как это работает
Раз в 3 часа бот получает актуальные лайки и метаданные обеих платформ. Он собирает кандидатов из нескольких поисковых запросов и уже сохранённой библиотеки, удаляет повторы по ID и лишь затем выбирает результат. Версии записи, состав артистов, длительность и ISRC остаются отдельными признаками. Ранг метаданных нужен для отбора и сортировки; он **не является вероятностью**.

Успешные сопоставления сохраняются в SQLite: при следующих запусках их поиск и Jev-проверка пропускаются, если оба трека по-прежнему в библиотеках и версия алгоритма не менялась. Метаданные треков не кешируются — списки лайков запрашиваются заново. Для новых пар сначала проверяется уже сохранённая библиотека; только если в ней не найдено подтверждённого совпадения, запускается поиск в каталоге. Между такими поисками выдерживается минимум 10 секунд. При лимите Spotify синхронизация завершается с ошибкой и сохраняет уже записанные пары вместо ожидания внутри клиента часами.

Режим `hybrid` работает без ключа Jev: точное совпадение названия, всех артистов и версии при подтверждающей длительности или ISRC принимается, спорные пары попадают в `/pending`. Если Jev включён, он проверяет лучших кандидатов и даёт финальное решение. Режим `jev_only` требует настроенного и включённого Jev: локальный ранг не определяет принятие или отказ. Jev проверяет до пяти разумных кандидатов. Вероятность от 0.85 допускает автоматическое сопоставление, от 0.55 до 0.85 требует одобрения, ниже 0.55 пара отклоняется. Кандидаты с разницей Jev менее 5 процентных пунктов отправляются на одобрение, если их нельзя считать одной записью на разных релизах. Разница ровно 5 пунктов уже не блокирует автоматическое принятие. Явное противоречие метаданных не принимается автоматически даже при высоком ответе Jev. При ошибке Jev синхронизация останавливается.

В обоих режимах действует общий фильтр цензуры: если в источнике нет её признаков, исключаются clean/censored/edited/amended/bleeped/non-explicit/family-friendly версии, radio/TV edits и названия с маскировкой вроде `***** Please II`. Признаки читаются из названия, поля версии и альбома. Для источника с признаком explicit исключается кандидат с explicit=false. Само по себе explicit=false не означает цензуру: у многих оригиналов нет откровенного текста. Среди подтверждённых вариантов одной записи предпочтение получает explicit/uncensored/dirty/unedited; пометка `(Explicit)` не считается отдельным ремиксом. Для clean или radio источника сохраняется его версия. Если подходящей версии нет, трек отклоняется, а не автоматически заменяется clean-версией. Jev получает структурированные признаки цензуры и инструкции сравнивать именно версии записи. Эти признаки доступны в диагностике `/pending`.

Версия алгоритма повышена до 4: при следующем `/sync` старые pending/failed переоцениваются, сохранённые пары проходят повторную проверку. Автоматического удаления треков из библиотек нет.

Пороги в `matching.py` подобраны по 105 реальным парам из библиотек Яндекс Музыки и Spotify с Jev через Vercel: 55 из 56 пар с сильными признаками одной записи получили не меньше 0.89; исключение — альбом с пометкой Remastered (0.20). Из 36 явно разных пар только одна получила больше 0.40 (0.60 при расхождении длительности на 24,5 секунды), и локальная проверка версии/длительности запрещает её автоматическое принятие. Яндекс Музыка в этой выборке не вернула ISRC, поэтому результаты не заменяют проверки на других библиотеках и провайдерах Jev.

При подмене недоступного лайкнутого трека Яндексом исходные метаданные берутся из `substituted`, а ID лайка сохраняется. Результат поиска оценивается по фактически предложенной записи. SQLite хранит историю решений и их происхождение; старые mappings можно переоценить через `/revalidate` без удаления лайков.

## Установка и запуск

Для собственного Spotify-приложения в Development Mode нужен активный Premium
у владельца приложения. При 403 с требованием Premium перевыпуск токена не помогает.
Для разового переноса сначала попробуйте https://music.yandex.ru/import.
Правила Spotify: https://developer.spotify.com/documentation/web-api/concepts/quota-modes

`auth_spotify.py` проверяет обязательные настройки до OAuth. Ошибки авторизации,
доступа, сети и лимитов объясняются в CLI и боте. Одинаковая фоновая ошибка
сообщается один раз до успешного прохода, изменения ошибки или перезапуска;
повторную диагностику можно вызвать через `/health`.

1. Склонируйте репозиторий:
   ```bash
   git clone https://github.com/meowflyx/MeowMusicSync.git
   cd MeowMusicSync
   ```

2. Установите зависимости:
   ```bash
   python3 -m venv .venv
   source .venv/bin/activate
   # На Linux может понадобиться: sudo apt install build-essential python3-dev
   pip install -r requirements.txt
   ```

3. Переименуйте `.env.example` в `.env` и впишите свои токены:
   - `TG_BOT_TOKEN` и `TG_ADMIN_ID` — для телеграм-бота (чтобы получать уведомления об ошибках и управлять процессом).
   - `SPOTIPY_CLIENT_ID`, `SPOTIPY_CLIENT_SECRET`, `SPOTIPY_REDIRECT_URI` — ключи приложения из Spotify Developer Dashboard (редирект ставьте `http://127.0.0.1:8888/callback`).
   - `YANDEX_MUSIC_TOKEN` — токен от Яндекс Музыки (можно вытащить через расширения браузера).

4. **ВАЖНО**: Первая авторизация Spotify!
   Запустите `auth_spotify.py`:
   ```bash
   python3 auth_spotify.py
   ```
   Скрипт выдаст ссылку. Перейдите по ней в браузере, согласитесь с доступом, скопируйте URL, на который вас перекинуло (даже если там страница ошибки локалхоста), вставьте обратно в терминал и нажмите Enter. Сгенерируется файл кэша `.cache`.

5. Запуск бота:
   ```bash
   python3 main.py
   ```

## Команды бота
- `/sync` — короткое имя `/sync_all`; основные команды доступны в меню Telegram.
- `/sync_all` — Принудительно запустить полную двустороннюю синхронизацию.
- `/sync_ym_sp` — Синхронизация Яндекс -> Spotify.
- `/sync_sp_ym` — Синхронизация Spotify -> Яндекс.
- `/status` — Статистика mappings, ожидающих решений и ненайденных треков.
- `/pending [страница]` — Показать до 5 треков на одобрение. Кнопками кандидатов выберите нужную запись, затем нажмите «Добавить». Выбранный вариант отмечен ✅; выбор сохраняется в БД. После решений обновляйте `/pending`: очередь сдвигается.
- `/retry_failed` — Сбросить записи ненайденных треков (следующая синхронизация попробует снова).
- `/list_failed` — Список ненайденных треков.
- `/clean_sp_dupes` — Удалить дубликаты из Spotify.
- `/clean_ym_dupes` — Удалить дубликаты из Яндекс Музыки.
- `/last_sync` — Информация о последней синхронизации (время и результат).
- `/logs [n]` — Последние n строк лога (по умолчанию 20, максимум 100).
- `/health` — Проверка доступности API Spotify и Яндекс Музыки.
- `/add_mapping <ym_id> <sp_id>` — Ручное сопоставление треков.
- `/like_playlist <ссылка>` — Добавить все доступные треки из личного плейлиста Яндекс Музыки в «Мне нравится».
- `/jev status` — Показать состояние проверки (без вывода ключа).
- `/jev typesafe <ключ>`, `/jev openrouter <ключ>`, `/jev vercel <ключ>` — Выбрать путь к Jev, сохранить ключ и включить проверку.
- `/jev off`, `/jev on` — Выключить или снова включить сохранённую настройку. По умолчанию Jev выключен.
- `/matching hybrid|jev_only` — Выбрать режим. `jev_only` доступен только с включённым Jev.
- `/revalidate` — Переоценить существующие mappings без повторного добавления лайков.
- `/help` — Список всех команд.

Ключ API шифруется перед записью в SQLite. Ключ шифрования создаётся автоматически в `.jev.key` с правами только для владельца и исключён из Git; резервная копия БД должна храниться вместе с копией `.jev.key`. Настраивать Jev можно только в личном чате с ботом. Команду с API-ключом бот пытается удалить из чата сразу после получения. Telegram уже получил это сообщение, поэтому после настройки при необходимости отзовите ключ и выдайте новый. Для включения Jev действительный API-ключ обязателен; при выключенном Jev ключ не нужен.

Поддерживаются [TypeSafe System One](https://github.com/typesafe-ai/typesafe-sdk-js/blob/main/src/client.ts), [OpenRouter Decisions API](https://openrouter.ai/blog/insights/what-is-jev/) и [Vercel AI Gateway Evaluate](https://vercel.com/changelog/ai-gateway-now-supports-typesafe-clients-and-http-api-for-jev). Для каждого пути нужен ключ соответствующего сервиса.

## Безопасность и уведомления

- Вместо сообщений о каждом треке бот присылает один итог синхронизации.
  Фоновый итог раз в 3 часа приходит без звука; ошибки — обычным сообщением.
- Синхронизация, одобрения и очистка не выполняются одновременно.
  Занятая операция предлагает повторить команду. Блокировка освобождается ОС
  при завершении процесса; поддерживается Linux, один аккаунт и общая папка БД.
- Очистка дубликатов требует повторить команду с `confirm`.
  Это нечёткий поиск, не гарантия идентичности записей; удалённые лайки не восстанавливаются автоматически.
- `wipe_ym_likes.py --confirm` удаляет **все** лайки Яндекса. Сначала остановите
  бота: при следующей двусторонней синхронизации лайки Spotify могут вернуться.
- При неполной библиотеке Яндекса или ошибке поиска синхронизация останавливается,
  чтобы не записывать ложные удаления/ненайденные треки. Уже выполненные добавления сохраняются.
